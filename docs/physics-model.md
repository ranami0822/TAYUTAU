# 物理層のモデル（実装の説明）

`src/sim/cpuSolver.ts`（参照実装）と `src/gpu/kernels.ts`（WGSL）が同じ計算をする。ここではその中身を式で書く。
設計メモ（`design-memo.md`）と調査（`research/08-implementation-roadmap.md`）の方針のうち、実際に採った形を記録する。

## 1. 格子と状態

- 領域: 1 辺 L = 5 cm の立方体、nx×ny×nz セル（既定 48³、h = L/48 ≈ 1.04 mm）、y が上。
- MAC 格子: 速度 u, v, w はセルの面に、比エンタルピー H [J/kg] はセル中心に置く。
- 各セルの質量は ρ₀h³（ρ₀ = 1000 kg/m³）で一定（非圧縮・Boussinesq 近似）。したがって
  - 質量の保存 ⇔ 速度場の発散がゼロ（圧力投影で保証）。
  - エネルギーの保存 ⇔ Σ H が保存（保存形の離散化で保証）。

- 水位: `waterLevel`（高さに対する割合）を行数に丸めた `waterRows` より上のセル（j ≥ waterRows）は空気。
  空気のセルは流れの計算では壁と同じに扱い（水面は剛体ふた近似: 法線速度 0、すべりあり）、熱の計算では何も出入りしない。
  質量・エネルギーの総和は水のセルだけで数える。真の自由表面（水面で圧力 0、水面が動く）は波の段階で入れる。

- 波: 水面の高さ η(x, z)（nx×nz）と面の流束 q を持ち、熱のサブサイクルごとに
  q ← (q − dt c²∇(η − η_f)/h)/(1 + γ dt)、η ← η − dt ∇·q/h + dt (w − w̄) を解く（c dt/h ≤ 0.5 になるよう波だけさらに細かく分割）。
  η_f = clamp(gain·w|w|/2g + lift·χ·B, ±cap)。w は水面直下のセルの下面の鉛直速度、χ は水面直下のセルの蒸気の割合、
  B は既定では 1（一定）。burstProb = p > 0 のときは列ごと・ステップごとのハッシュで確率 p のとき 1/p、それ以外 0
  （CPU と GPU で同じ整数ハッシュとステップ数を使う）。凍った列の面では q = 0。
  w は水面直下のセルの下面の鉛直速度、w̄ は凍っていない列での平均（GPU では 1 ワークグループで縮約）。
- 動かしている熱源: 熱源の速度（ドラッグの移動量 ÷ そのフレームのシミュレーション時間、速度上限で頭打ち）を
  パラメータに入れ、速度の移流の直後に、球の中の面の速度を熱源の速度で置き換える。そのあと圧力投影で周囲の流れが決まる。

## 2. エンタルピーと相（`src/sim/water.ts`）

基準: H = 0 は 0 °C の氷。H_B = L_f + 100 c_w（100 °C の飽和水）。

| 範囲 | 状態 | 温度 |
|---|---|---|
| H < 0 | 氷 | H / c_ice |
| 0 ≤ H < L_f | 融解中（液の割合 H/L_f） | 0 °C |
| L_f ≤ H < H_B | 水 | (H − L_f) / c_w |
| H_B ≤ H < H_B + L_v | 沸騰中（蒸気の割合 χ = (H − H_B)/L_v） | 100 °C |
| H ≥ H_B + L_v | 蒸気 | 100 + (H − H_B − L_v) / c_v |

Stefan 条件（界面での潜熱の出入り）は陽に追わず、この H–T 関係に埋め込まれている（エンタルピー法）。
氷の割合が 0.5 を超えたセルを固体とし、そのセルに接する面の速度を 0 にする。

## 3. 1 ステップ（dt = 1/120 s）

1. 熱（`subcycles` = 4 回に分けて、各 dts = dt/4）
   1. 熱源: 球の中のセルで dH = (h_c / (ρ₀h)) (T_s − T) dts。熱源の温度を超えないように頭打ち。
      加えた量はセルごとに `srcAcc` に積算する（エネルギー収支の帳簿）。
   2. 熱伝導: 面ごとの流束 k_f (T_nb − T)/h、k_f は両セルの調和平均（壁は断熱）。
   3. 蒸気の上昇（ドリフト）: 鉛直の面で、下のセル a の蒸気が上のセル b の液と入れ替わる。
      入れ替わる割合 x = c_D χ_a (1 − χ_b)、c_D = w_b (g/9.81) dts / h。
      上へ運ばれるエンタルピーは x (max(H_a, H_vsat) − clamp(H_b, L_f, H_B))。
      b が過冷水なら、受け取った潜熱で温まる（凝縮）。
   4. 移流: 保存形の MUSCL（minmod 制限）。面の流束を隣り合う 2 セルが同じ式で計算するので、総和は丸め誤差を除いて保存する。
2. 速度
   1. RK2 のセミラグランジュ移流、v には浮力 b を加える:
      b = g [ (ρ_ref − ρ_l(T)) + s_v α(χ) (ρ_l(T) − ρ_v) ] / ρ_ref、ρ_l は Kell (1975)、α はボイド率、s_v はゲーム用の縮小係数。
   2. 渦度閉じ込め f = ε h (N × ω)。
   3. 発散 → 赤黒 SOR（40 反復、ω = 1.6、前ステップの値から開始）→ 勾配を引く。固体セルは Neumann 境界。
   4. 各成分を v_max（保存形移流の CFL 条件から決めた上限）で制限。

## 4. GPU での実行

- すべての場は StorageBuffer に置き、カーネルは 1 次元ディスパッチ（ワークグループ 64）。
- ピンポンは「別のカーネルとして書く」形にした（thermal: H → Htmp、advectScalar: Htmp → H など）。
  Babylon の ComputeShader のバインドを毎回付け替えないため。
- パラメータ（熱源の位置など）は 1 フレームに 1 回だけ書き込む。Babylon は 1 フレームのディスパッチをまとめて送信し、
  `writeBuffer` はそれより先に適用されるため、フレームの途中で書き換えると全ディスパッチに最後の値が見えてしまう。
- 描画は H のバッファをそのままフラグメントシェーダーで読む（ボリュームのレイマーチング）。HUD 用の総和だけ GPU 上で
  ワークグループごとに縮約し、小さな配列を読み戻す。

## 5. 確かめていないこと（未確認）・割り切り

- 圧力は 1 気圧で一定。沸点・融点は固定。
- 氷は水と同じ密度として扱うので、浮かず、体積も増えない。凍った場所にそのまま固まる。
- 液体の過熱（100 °C を超える液）、核生成の待ち時間、膜沸騰は扱わない。
- 蒸気は液と同じ格子上の「質量割合」として持ち、体積の膨張は表さない（蒸気が上部にたまる様子は、上部のセルの χ が 1 に近づくことで表す）。
- 熱伝達係数、泡の上昇速度の実際の値は桁のみ（未確認）。
- 移流の数値拡散が分子粘性・熱拡散より大きい（粗い格子のため）。
- 速度の上限は、強い沸騰流で実際の速度より遅くなる。
